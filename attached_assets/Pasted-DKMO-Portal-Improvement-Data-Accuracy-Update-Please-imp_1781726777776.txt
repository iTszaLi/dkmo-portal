SAMPLE DATA & TEST RECORDS

To ensure every module can be properly tested and reviewed, please populate all newly created or updated pages with realistic sample records where actual DKMO data does not yet exist.

Requirements:

* Do not leave tables, cards, reports, dashboards, or sections completely empty.
* Display 5–10 sample rows/records in each module for testing purposes.
* Sample records must clearly be marked as test/demo data and must not affect real DKMO records.
* Once actual DKMO data exists, the system should automatically replace demo content with real data.

Examples:

Members Module:

* Show 5–10 sample member records if no members exist.

Meeting Attendance:

* Show 5–10 attendance entries for testing.
* Include Present and Absent examples.

Reports:

* Show sample report rows if no data exists.

Committee Performance:

* Show sample performance records only when no real records are available.

Recruitment Leaderboard:

* Show realistic sample rankings only when no referral data exists.

Member Profile:

* Display example payment history, document records, and activity history when testing.

Dashboard:

* Display sample statistics only when the database is empty.

Important:

* Never use hardcoded fake values when real DKMO records are available.
* Real database records must always take priority.
* Sample data should exist only to demonstrate functionality and prevent blank screens during testing.
* Clearly identify demo/test records so administrators can distinguish them from actual DKMO data.

Goal:

Every module should be visually complete and testable during development, while still using real DKMO data whenever available.

Goal:

Make the portal simple, professional, accurate, and fully driven by actual DKMO data while maintaining stability and ease of use.
