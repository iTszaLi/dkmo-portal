# 3. DASHBOARD — REGRESSION TESTS

Relevant file:

* `artifacts/api-server/src/routes/dashboard.ts`

Verify dashboard metrics are calculated from the real database.

### Total Members

Must use the actual member records.

### Active Members

Must use the same active-member status logic used by the Members module.

Do not create a separate conflicting definition.

### Membership Fees Pending

Must come from the actual membership ledger/payment state.

### Total Membership Fees Collected

Must equal the total of **actually collected membership fees** from the membership ledger.

Rules:

* Membership fee = SAR 100 one-time fee.
* Include paid membership fees.
* Exclude FRF payments.
* Exclude loan transactions.
* Do not count unpaid/pending records as collected.
* Do not hardcode the total.

### Loan Money Outstanding

Verify:

`Loan Money Outstanding = Total Loan Principal Disbursed - Total Principal Repaid`

Exclude:

* Rejected loans
* Cancelled loans
* Undisbursed loans
* Fully repaid loans

The result should be SAR 0 when there are no outstanding loans.

# 4. FRF SINGLE ACTIVE CASE REGRESSION

This is extremely important because the dashboard and FRF modules depend on this rule.

Verify:

* There can be **only one active FRF collection case at a time**.
* Approving an FRF claim opens the next collection case.
* A new collection case cannot become active while another case is still active.
* When there is no active case:

  * Active FRF Case = 0
  * FRF Outstanding = SAR 0
  * FRF Fees should show no active collection case.
* FRF member eligibility must still follow the membership rule:

  * Membership Paid → FRF Active/Eligible
  * Membership Unpaid/Pending → FRF Inactive/Not Eligible

Do not allow the regression tests to create multiple active FRF cases.
